# 19 · 系统板块重梳与 PR 推进计划 — 2026-05-18

## 一、当前动作：暂停功能开发

从本文件建立起，TDL 项目先暂停继续新增功能。

暂停的不是项目推进，而是暂停“直接写代码加能力”的节奏。当前更重要的是把 `18-项目落地实现路径` 里涉及的系统板块重新梳理一遍，确认每个板块的方向、边界、落地条件和验收方式。`18 V1` 是起点，`18 V2` 是本轮重梳后的当前主口径。

原因：

1. 项目已经从“任务助手”扩展到“企业经营操作系统雏形”，不能继续按单点功能补丁推进。
2. 会议录入已经暴露出高风险边界：AI 容易把愿望、倡导、讨论苗头深加工成伪决议。
3. 知识层、插件、多 agent、跨系统接入都具备长期价值，但如果过早进入开发，会稀释当前主链路的可信度。
4. 后续每一次方向调整都应进入 Git 历史和 PR 审核流程，避免文档漂移。

## 二、本轮重梳的目标

本轮不追求新增生产能力，只产出可被审核、可被执行的路线校准。

目标：

1. 把 `18` 中的五个落地维度拆成可检查板块。
2. 校准旧文档中仍停留在“会议纪要直接拆决议/TDL”的表述。
3. 明确哪些内容近期做，哪些内容只保留为阶段 2 / 3 / 4 的方向。
4. 固化“文档更新也必须走 PR”的协作纪律。
5. 为后续重新恢复开发提供一张优先级清楚的路线图。

## 四、PR 推进规则

从现在起，项目更新分成两类 PR。

### 1. 文档校准 PR

适用场景：

- 调整项目方向
- 调整阶段路线
- 调整判定口径
- 调整协作方式
- 更新试点结果和评测结论

要求：

1. 每个 PR 只解决一个清晰主题。
2. PR 描述必须写明“本次更新改变了什么决策”。
3. 涉及 17 号冻结基线时，不修改 17，只新增 V2/V3 或在其他文档记录差异。
4. 重要文档 PR 仍按 `10-Codex-Claude-PR协作SOP` 交给 Claude review。
5. Claude review 结论和用户最终拍板要进入 PR 讨论或后续文档记录。

### 2. 功能开发 PR

适用场景：

- 修改后端代码
- 新增数据库迁移
- 新增交互卡片
- 修改 AI prompt / schema / evaluator
- 修改部署配置

要求：

1. 只有在相关文档口径稳定后才启动。
2. 每个功能 PR 必须有测试或明确说明无法自动化测试的真实验证方式。
3. 不得把知识层远期设计提前实现成正式表结构。
4. 涉及用户可见交互时，必须回到 `14-按钮交互全场景验证清单` 做验证。

## 五、建议的 PR 顺序

### PR-A：项目路线与文档治理校准

目标：

- 新增本文件。
- 更新阅读指引。
- 更新 `10` 的文档 PR 规则。
- 在旧核心文档中标注当前应以 `16 / 17 / 18 / 19` 为准。

验收：

- 后续读者不会误以为当前应该继续直接开发会议录入或插件。
- 后续每次调整都能自然进入 PR 节奏。

### PR-B：会议分类 schema 与 gold set 设计

目标：

- 把 `事实 / 已明确事项 / 待处理议题 / 火花设想 / 观察线索` 变成可评测 schema。
- 明确 `What + Who + When` 字段。
- 建立伪决议评测口径。

验收：

- 任意一条会议片段都能被标注为成熟度 + 对象类型 + 证据来源。
- `已明确事项` 不满足三要素时必须降级。

### PR-C：5 月月会材料重新标注

目标：

- 按 PR-B 的 schema 重新处理 5 月月会材料。
- 不做深加工，不把推断当事实。
- 产出可作为后续模型评测对照组的人工基准。

验收：

- Frank 看后不再出现“熟悉又陌生”的错位感。
- 每条可转 TDL 的内容都有原文证据和三要素。

### PR-D：日常 TDL 试点验收闭环

目标：

- 只围绕 Frank + 李珍试用。
- 验证按钮、文本兜底、语音、日历、拒绝路径、暂缓路径。

验收：

- 能明确回答“当前是否可投入小范围真实使用”。
- 所有明显影响信任的交互问题有修复优先级。

当前落地结论见：

- `23-日常TDL试点验收闭环-2026-05-18.md`
- 当前判定为 `pilot`，可继续 Frank + 李珍两人试用，但提醒端真实交互未过关，暂不扩大推广。

### PR-E：恢复功能开发

只有 PR-A 到 PR-D 完成并通过 review 后，再恢复代码开发。

优先候选：

1. follow-up 纠错继续打磨。
2. 人名模糊匹配与同音字维护闭环。
3. 会议分类 schema / evaluator。
4. 按钮体验修复。

## 六、当前不做清单

1. 不新增知识层正式数据库表。
2. 不开发战略对齐与蓝图管理、经营复盘与策略建议等上层插件。
3. 不扩展成多个运行时 agent。
4. 不把 5 月月会材料直接创建成正式 TDL。
5. 不把旧文档里“会议纪要 -> 决议 -> TDL”的表述继续当作当前开发口径。

## 七、恢复开发的条件

满足以下条件后，再恢复功能开发：

1. 18 号文档的阶段路线已经被拆成可执行 PR 队列。
2. 旧文档中的核心冲突口径已经标注或修正。
3. 会议内容判定标准已经固化到 schema / gold set。
4. 日常 TDL 试点的按钮和纠错问题已经有真实验证记录。
5. 用户确认下一轮开发优先级。

## 八、当前结论

当前最应该做的不是继续加功能，而是先把系统开发方向重新压实。

短期节奏应调整为：

`暂停新增开发 -> 文档体系校准 -> Claude review -> 用户拍板 -> 合并 PR -> 再恢复功能开发`

# 28 · R5 工作通知入口排查清单 — 2026-05-22

## 一、问题定义

`R5` 指用户从钉钉工作通知里的应用入口点击后，应回到 `TDL 助手` 私聊或可继续操作的卡片上下文。

当前真实现象：

- 2026-05-20 复测失败。
- 用户点击工作通知里的应用入口后，进入钉钉广告页。
- 后端没有可控的私聊跳转配置项。
- 当前兜底是在反馈消息里追加：`继续处理请回到 TDL 助手私聊。`

已确认不属于以下问题：

- 不是 backend / stream bot 服务离线。
- 不是提醒卡按钮不可点击。
- 不是卡片回调未写回状态。
- 不是反馈消息发送失败。

证据见：

- `logs/2026-05-19-钉钉提醒互动卡真实验证.md`
- `logs/2026-05-22-R5真实客户端入口观察记录.md`
- `design/14-按钮交互全场景验证清单-2026-05-18.md`
- `design/23-日常TDL试点验收闭环-2026-05-18.md`

## 二、排查原则

按 `24-低耗协作与真实运维工作流` 执行：

1. 先跑脚本和命令行，确认服务、配置和模板状态。
2. 再查仓库内可验证的后端事实。
3. 最后才进入钉钉管理后台或真实客户端。
4. 修改钉钉后台配置前，必须由 Frank 确认。

## 三、命令行预检查

先在本地运行：

```bash
bash scripts/tdl-prod-check.sh
```

必须确认：

- `backend=active`
- `stream=active`
- `intake_worker=active`
- `pilot_metrics_timer=active`
- `health={"status":"ok"}` 或等价健康响应
- `template_set=True`
- `require_interactive=True`

如果这里不通过，先修生产服务，不进入钉钉后台。

## 四、仓库侧已知事实

当前反馈消息由 `TDLCardCallbackHandler` 调用 `_send_card_action_feedback()` 发送，底层是钉钉工作通知 markdown。

仓库内可控项：

- `DINGTALK_AGENT_ID`
- `DINGTALK_TDL_CARD_TEMPLATE_ID`
- `DINGTALK_REQUIRE_INTERACTIVE_REMINDER_CARDS`
- 反馈消息正文里的兜底提示

仓库内暂未发现可控项：

- 工作通知应用图标点击后的目标页面。
- 工作通知入口直接打开机器人私聊。
- 工作通知入口绑定某个 H5 页面或会话页。

因此 R5 的主排查方向应是钉钉后台应用/机器人入口配置，而不是后端代码。

## 五、钉钉后台检查项

需要有钉钉开发者后台权限的人检查：

| 检查项 | 目标 |
|---|---|
| 工作通知所属应用 | 确认发送工作通知的 `agent_id` 对应 `TDL 管理助手` 应用 |
| 应用首页地址 | 避免首页指向默认广告页或未配置页面 |
| 机器人关联 | 确认应用入口是否能关联到当前 Stream 机器人 |
| 应用可见范围 | 确认 Frank / 李珍在应用可见范围内 |
| H5/微应用入口 | 如果不能跳私聊，确认是否能跳到一个明确的 TDL 帮助页 |
| 工作通知打开行为 | 查钉钉是否支持工作通知点击后打开机器人会话；如果不支持，记录为平台限制 |

## 六、真实端复测步骤

复测前先确认生产状态：

```bash
bash scripts/tdl-prod-check.sh
```

复测动作：

1. 由 Frank 创建一条测试 TDL。
2. 触发一次卡片按钮动作，例如 `标记完成` 或 `暂缓`。
3. 确认收到工作通知反馈。
4. 点击工作通知中的应用入口或应用图标。
5. 记录打开后的页面：
   - 是否进入 `TDL 助手` 私聊。
   - 是否进入可继续处理的 TDL 页面。
   - 是否仍进入广告页。
6. 截图或文字记录结果，追加到 `logs/2026-05-19-钉钉提醒互动卡真实验证.md`。

如果只需要复测工作通知中的网页入口链接，可先用 dry-run 预览消息：

```bash
python scripts/send-r5-entry-test-notification.py \
  --user-id <dingtalk_user_id>
```

确认收件人和链接无误后，再显式发送：

```bash
python scripts/send-r5-entry-test-notification.py \
  --user-id <dingtalk_user_id> \
  --send
```

## 七、判定口径

| 结果 | 判定 |
|---|---|
| 点击入口进入 TDL 助手私聊 | `pass` |
| 点击入口进入明确的 TDL 处理页，并能回到私聊 | `partial` |
| 点击入口进入广告页、空白页、无关应用页 | `fail` |
| 钉钉确认不支持工作通知跳机器人私聊 | 记录为平台限制，保留反馈消息兜底 |

## 八、当前建议

在 R5 未通过前：

1. 保留反馈消息里的 `继续处理请回到 TDL 助手私聊。`
2. 不把 R5 作为 Frank + 李珍继续试用的阻塞项。
3. 继续把 R5 作为扩大推广前的阻塞项。
4. 不为 R5 盲目新增后端跳转逻辑，除非钉钉后台确认存在可配置目标。

如钉钉后台确认无法把工作通知入口直接跳转到机器人私聊，可采用最小网页入口作为过渡方案：

- 后端入口：`/` 和 `/entry`
- 生产 URL：`https://libu-h5.bdteach.cn/tdl/`
- 作用：承接钉钉网页应用首页，避免用户从工作通知入口进入广告页或空页面。
- 限制：该页只做明确提示，不承诺网页端任务操作；任务处理仍回到 `TDL管理助手` 私聊完成。

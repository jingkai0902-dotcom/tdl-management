# 31 · 管理工作台 V0 验收清单 — 2026-05-24

## 一、本文定位

本文承接 `30-管理工作台与钉钉通道化路线校准`，用于定义管理工作台 V0 的真实试用验收方式。

V0 的目标不是证明工作台已经是完整产品，而是验证：

> Frank（荆少巍）+ Helen（李珍）每天打开工作台后，是否能比钉钉任务卡更清楚地看到当前要处理什么、什么已经卡住、什么需要确认。

## 二、验收边界

V0 只验收只读工作台。

允许：

1. 查看今日。
2. 查看本周剩余。
3. 查看逾期 / 临期。
4. 查看进行中。
5. 查看待确认 / 待判断。
6. 按 `owner_id` 查看个人视角。
7. 只在受控试验环境开启 `WORKBENCH_V0_ENABLED`。

不允许：

1. 创建任务。
2. 修改任务状态。
3. 发送钉钉消息。
4. 写入日历。
5. 触发 agent 执行动作。
6. 接入会议待复核、议题池、火花池、观察线索。
7. 把 `owner_id` 筛选当作身份认证或权限控制。

## 三、试验对象

| 角色 | 验收重点 |
|---|---|
| Frank / 荆少巍 | 全局管理视角、技术可维护性、是否值得继续投资工作台方向 |
| Helen / 李珍 | 业务理解、真实使用体验、是否比钉钉任务卡更清楚 |

业务体验以 Helen / 李珍为主参照。

技术实现、部署和维护风险以 Frank / 荆少巍为主参照。

## 四、每日试用动作

每天至少做一次：

1. 通过约定的固定链接、浏览器收藏或桌面快捷入口打开 `/workbench/view`，不要求手动输入网址。
2. 查看顶部五个区块数量。
3. 查看今日、本周剩余、逾期 / 临期三个列表。
4. 查看待确认 / 待判断是否能帮助发现未闭环任务。
5. 若使用个人视角，打开带 `owner_id` 的接口或后续入口。
6. 记录当天发现的问题。

同时记录入口体验：

1. 当天是否主动想起打开工作台。
2. 打开动作是否觉得麻烦。
3. 是否因为没有主动提醒而漏看。
4. 是否需要由钉钉简洁通知提供跳转入口。

## 五、验收问题

### 5.1 信息是否有用

1. 今日列表是否准确反映当天要处理的任务。
2. 本周剩余是否能帮助判断本周还剩哪些推进事项。
3. 逾期 / 临期是否能突出真正需要关注的风险。
4. 进行中是否有助于看到当前开放任务总量。
5. 待确认 / 待判断是否能帮助处理草稿和不完整任务。

### 5.2 是否比钉钉任务卡更清楚

1. 是否比在钉钉消息里翻任务更快。
2. 是否更容易看到全局。
3. 是否更容易发现卡住的事项。
4. 是否减少“我不知道现在该看哪条”的感觉。
5. 是否仍需要钉钉提供主动提醒。

### 5.3 小团体协作是否成立

1. Helen 是否能理解每个区块的含义。
2. Helen 是否能判断哪些任务需要自己处理。
3. Frank 是否能从工作台看到 Helen 的试用问题。
4. 是否需要为 Helen 保留部分钉钉内轻操作。
5. 是否需要区分 Frank 全局视角和 Helen 个人视角。

### 5.4 技术边界是否守住

1. 页面是否只读。
2. 是否没有误导用户以为可以在页面上完成任务。
3. 数据来源是否清楚。
4. 同一任务出现在多个区块时，用户是否能理解这是多维视角。
5. 页面失败时是否不会影响钉钉提醒和现有 TDL 链路。
6. 试验入口是否只在受控环境启用，未误认为已经具备正式权限隔离。

### 5.5 入口是否足够轻

1. 固定链接或收藏入口是否足以支撑每日打开。
2. Frank 和 Helen 是否需要被提醒后才会打开工作台。
3. 工作台有用但打开麻烦，是否成为实际使用阻碍。
4. 如果需要钉钉提供入口，最小形态是否只需简洁通知和跳转，而不恢复复杂任务卡。

## 六、通过标准

V0 通过需要同时满足：

1. Frank 认为工作台比钉钉任务卡更适合作为主交互面候选。
2. Helen 能理解五个区块，并认为它比钉钉任务卡更容易看清任务状态。
3. 至少连续 3 个工作日使用后，没有出现严重误导。
4. 工作台只读边界没有被突破。
5. 试用中发现的问题可以通过 V0.1 小迭代解决，而不是证明方向错误。
6. 能区分“信息结构无价值”和“信息有价值但入口摩擦过高”这两类失败原因。

## 七、不通过标准

出现以下任一情况，应暂停继续开发工作台能力：

1. Helen 无法理解区块含义，且解释后仍难以使用。
2. Frank 仍主要依赖钉钉任务卡才能判断工作状态。
3. 工作台展示的信息与真实任务状态频繁不一致。
4. 多维重复计数造成明显误解。
5. 只读页面无法带来比钉钉任务卡更清楚的管理视角。

## 九、下一步候选

只有 V0 通过后，才考虑：

1. 更清晰的个人视角入口。
2. 更友好的移动端页面。
3. 任务详情只读页。
4. 每日摘要。
5. 周报草稿。
6. 极少量、可测试、可回滚的写入能力。

写入能力必须另走设计和测试，不在 V0 验收范围内。

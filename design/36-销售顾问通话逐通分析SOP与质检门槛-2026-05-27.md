# 36 · 销售顾问通话逐通分析 SOP 与质检门槛 - 2026-05-27

## 一、本文背景

2026-05-27，Helen 在自己的 Codex 环境中处理销售顾问电话转录材料时出现严重质量问题：

1. 服务器上已有多位顾问、多通电话转录文本上传成功。
2. Codex 被要求进行分析后，产出目录混乱，无法清楚判断哪通电话对应哪个顾问。
3. 后续整理为顾问维度的 `r1 / r2 / r3` 分析结果后，仍出现内容单薄、结构不对、证据不足的问题。

初步判断：

> 根因不是单纯的模型能力问题，而是任务编排错误。多顾问、多通电话被批量分析后，输入上下文过大，模型必然压缩、忽略和删减细节，导致输出变薄、归属混乱、证据链断裂。

本文用于建立销售顾问通话分析的硬性操作规则，避免再次发生“批量跑完但不可用”的结果。

## 二、核心结论

正式确认：

> 销售顾问通话分析必须按“一通电话一个分析单元”执行。批量流程只允许用于发现文件、建立索引和排队，不允许用于合并分析多通电话。

本规范适用于：

1. 销售顾问电话录音转写文本。
2. 面咨、回访、邀约、续费、盘单等一对一沟通材料。
3. 后续任何以“单通沟通质量”为评价对象的 AI 分析。

不适用于：

1. 月度会议整体转录分析。
2. 管理层会议纪要提取。
3. 已人工汇总后的部门级报告。

这些材料可以另用会议或经营分析规范处理。

## 三、不可违反的硬规则

### 3.1 一通电话一个任务单元

每次分析只能处理一通电话转录文本。

禁止：

1. 一次把某顾问多通电话全部丢给 AI 分析。
2. 一次把多位顾问的转录文本合并分析。
3. 先批量生成薄摘要，再试图补充细节。
4. 用“r1 / r2 / r3”替代真实的电话编号、顾问、时间和来源路径。

允许：

1. 批量扫描服务器目录，找出待分析文件。
2. 建立待分析清单。
3. 按清单逐通排队。
4. 每通电话独立分析、独立质检、独立归档。

### 3.2 一通电话一个目录

每通电话必须有独立目录，目录名必须能追溯顾问和通话。

推荐目录格式：

```text
顾问姓名__YYYYMMDD-HHMM__call-来源编号/
  00-source.txt
  01-analysis.md
  02-qc.md
  03-final.md
```

如果缺少时间或来源编号，必须使用占位并记录缺口：

```text
顾问姓名__unknown-time__call-原文件名/
```

禁止：

1. 只按顾问建一个大目录，把多通电话分析混在一起。
2. 只用 `r1 / r2 / r3` 作为文件夹或分析编号。
3. 只保留分析结果，不保留原始转录文本副本或来源路径。

### 3.3 每通电话必须保留来源证据

每份分析必须能回答：

1. 这是哪位顾问的电话。
2. 原始转录文件在哪里。
3. 这通电话发生在什么时候，若未知则明确标记未知。
4. 分析结论引用了哪些原文证据。
5. 哪些结论只是推断，不能当作事实。

### 3.4 先质检，再汇总

单通电话分析未通过质检前，不允许进入顾问汇总、部门汇总或回传工作台。

禁止：

1. 先批量生成所有顾问汇总，再回头检查单通质量。
2. 未经质检就把结果回传到业务看板。
3. 用“整体看起来差不多”代替逐通质量检查。

## 四、标准执行流程

### 4.1 第一步：只做文件发现，不做内容分析

Codex 可以先扫描服务器或目录，输出待分析清单。

清单字段：

| 字段 | 要求 |
|---|---|
| call_id | 临时唯一编号，可由文件名生成 |
| consultant | 顾问姓名；无法判断则写 `unknown` |
| source_path | 原始转录文件路径 |
| call_time | 通话时间；无法判断则写 `unknown` |
| transcript_length | 字数或行数 |
| status | `pending` / `analyzing` / `qc_passed` / `qc_failed` |
| notes | 缺失信息或异常 |

文件发现阶段禁止输出业务判断。

### 4.2 第二步：逐通建立工作目录

每条 `pending` 记录建立独立目录，并复制或引用原始转录。

目录内至少包含：

| 文件 | 作用 |
|---|---|
| `00-source.txt` | 原始转录文本副本，或明确写入原始路径和内容快照 |
| `01-analysis.md` | 单通电话结构化分析 |
| `02-qc.md` | 质检结果 |
| `03-final.md` | 通过质检后的最终版 |

若因权限或体积原因不能复制原文，`00-source.txt` 必须写清：

```text
原始文件路径：
文件名：
顾问：
通话时间：
未复制原因：
```

### 4.3 第三步：单通电话结构化分析

每通电话分析必须使用固定结构。

```text
# 单通电话分析

## 1. 基本信息

- 顾问：
- 通话时间：
- 原始文件：
- 本次分析编号：
- 转录质量：（高 / 中 / 低）
- 是否存在明显缺段或说话人混乱：

## 2. 通话目的判断

- 本通电话主要目的：
- 当前客户阶段：（邀约 / 需求了解 / demo 前沟通 / demo 后跟进 / 续费 / 异议处理 / 其他）
- 判断依据：

## 3. 客户关键信息

- 客户明确表达的需求：
- 客户明确表达的顾虑：
- 客户当前决策状态：
- 是否出现关键家庭/孩子/时间/价格/竞品信息：
- 原文证据：

## 4. 顾问表现

- 做得好的地方：
- 明显问题：
- 是否有追问：
- 是否有确认客户真实顾虑：
- 是否有清晰推进下一步：
- 原文证据：

## 5. 销售流程判断

- 是否完成本阶段应做动作：
- 是否遗漏关键动作：
- 下一步是否明确：
- Who / What / When 是否清楚：

## 6. 可训练点

- 需要反馈给顾问的 1-3 个训练点：
- 每个训练点对应的原文证据：
- 建议如何改说：

## 7. 风险与机会

- 成单 / 续费 / 到访风险：
- 可利用机会：
- 需要主管介入的事项：

## 8. 不确定项

- 因转录质量或上下文不足无法判断的内容：
- 需要人工补充的信息：
```

分析必须包含原文证据。没有证据的判断应写入“不确定项”，不得包装为事实。

### 4.4 第四步：逐通质检

质检文件 `02-qc.md` 使用固定检查表：

```text
# 单通电话分析质检

## 1. 归属检查

- [ ] 顾问姓名明确
- [ ] 原始文件路径明确
- [ ] 通话时间明确；若未知，已标记 unknown
- [ ] 目录名与分析内容一致

## 2. 完整性检查

- [ ] 已判断通话目的
- [ ] 已提取客户需求
- [ ] 已提取客户顾虑
- [ ] 已评价顾问表现
- [ ] 已判断下一步是否明确
- [ ] 已列出训练点
- [ ] 已列出不确定项

## 3. 证据检查

- [ ] 关键判断均有原文证据
- [ ] 没有把推断写成事实
- [ ] 没有引用其他电话内容
- [ ] 没有混入其他顾问内容

## 4. 输出质量检查

- [ ] 内容不是空泛摘要
- [ ] 训练点具体、可执行
- [ ] 问题描述能对应到话术或流程动作
- [ ] 可供主管复盘使用

## 5. 质检结论

- 结论：通过 / 不通过
- 不通过原因：
- 需要返工的部分：
```

只要任一关键项不满足，即 `qc_failed`，必须返工，不得进入汇总。

### 4.5 第五步：单通通过后再做顾问汇总

只有某顾问的多通电话均已逐通通过质检，才允许生成顾问维度汇总。

顾问汇总必须引用已通过的 call_id：

```text
# 顾问通话汇总

## 覆盖范围

| call_id | 通话时间 | 客户阶段 | 质检状态 |
|---|---|---|---|

## 稳定优点

## 重复问题

## 最需要训练的 3 个能力

## 主管复盘建议

## 不足以判断的内容
```

禁止在顾问汇总中引入没有通过单通质检的电话。

## 五、质检通过标准

一份单通电话分析必须同时满足以下条件：

1. 归属清楚：顾问、原始文件、通话时间或 unknown 标记齐全。
2. 结构完整：基本信息、客户信息、顾问表现、流程判断、训练点、不确定项齐全。
3. 证据充分：关键判断有原文证据。
4. 不混淆：没有跨顾问、跨电话内容污染。
5. 有训练价值：至少能产出 1 个具体可执行训练点，或明确说明本通电话不足以训练。
6. 可追溯：主管能从最终结果回到原始转录。

未满足以上任一条件，不得回传、不得汇总、不得作为顾问评价依据。

## 六、目录与命名规范

推荐根目录结构：

```text
call_analysis/
  inbox/
    pending_index.csv
  consultants/
    顾问A/
      顾问A__20260527-1430__call-001/
        00-source.txt
        01-analysis.md
        02-qc.md
        03-final.md
      顾问A__20260527-1605__call-002/
        ...
    顾问B/
      ...
  summaries/
    顾问A__summary__20260527.md
  qc_reports/
    qc_failed__20260527.md
```

命名字段说明：

| 字段 | 说明 |
|---|---|
| 顾问姓名 | 使用业务侧确认姓名 |
| `YYYYMMDD-HHMM` | 通话时间；未知则 `unknown-time` |
| `call-001` | 来源编号或临时编号 |
| `r1 / r2 / r3` | 只能作为分析轮次，不得作为电话编号 |

如果确实需要多轮分析，写成：

```text
01-analysis-r1.md
01-analysis-r2.md
01-analysis-r3.md
```

但最终必须收敛到 `03-final.md`。

## 七、批量能力的允许边界

### 7.1 允许批量做的事

1. 扫描目录，统计待分析文件数。
2. 生成 `pending_index.csv`。
3. 检查哪些电话缺顾问、缺时间、缺原文。
4. 检查哪些目录缺 `01-analysis.md`、`02-qc.md` 或 `03-final.md`。
5. 汇总已通过质检的结果。

### 7.2 禁止批量做的事

1. 批量读取多通电话并一次性生成分析。
2. 批量跨顾问生成训练建议。
3. 在未逐通质检前生成顾问排名或能力评价。
4. 将多通电话压缩成一个“总体摘要”后再补细节。
5. 将未经质检的分析回传到工作台或正式看板。

## 九、回传工作台前的准入门槛

销售通话分析结果未来如需进入工作台或经营看板，必须先满足：

1. 单通电话 `03-final.md` 存在。
2. 对应 `02-qc.md` 结论为通过。
3. 顾问姓名、来源文件、通话时间或 unknown 标记齐全。
4. 分析结果不含未脱敏的高敏感个人信息。
5. 回传内容区分：
   - 单通事实。
   - 顾问训练建议。
   - 主管待处理事项。
   - 不确定项。
6. 有人工确认人。

未满足以上条件，只能保留在分析工作区，不得进入正式工作台。

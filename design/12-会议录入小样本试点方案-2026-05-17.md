# 12 · 会议录入小样本试点方案 — 2026-05-17

## 一、试点目标

会议录入不直接进入全量生产任务池，先做小样本评测。

本轮目标不是证明模型“能拆任务”，而是验证它能不能稳定做到：

1. 只提取明确动作，不把经营判断、背景讨论、复盘感悟误建为 TDL。
2. 正确识别负责人，尤其是管理层姓名和语音转录近似字。
3. 截止时间不编造，原文未明确时保持为空。
4. 保留可验收的完成标准，不写成空泛表述。
5. 多份材料中的同义动作能合并，不重复建项。

## 二、数据范围

本轮使用 `励步5月月度会/` 下 7 份真实材料：

1. `2026.5.9会议_原文.docx`

## 三、执行顺序

### 第一步：离线抽取

把 7 份材料先转成纯文本，不直接调用生产 `/meetings/parse`。

要求：

- 每份材料保留来源文件名。
- 表格材料保留 sheet 名、行列关系和关键字段。
- 会议原文保留时间戳或段落顺序。
- 不在文本整理阶段人工改写任务表达。

### 第二步：模型生成候选任务

使用会议录入解析能力生成候选任务，但先只落成评测文件，不写入正式 TDL 表。

候选任务至少包含：

| 字段 | 要求 |
|---|---|
| title | 可执行动作 |
| owner | 负责人；不确定则为空 |
| due_at | 明确截止时间；不确定则为空 |
| completion_criteria | 完成标准；原文没有则为空 |
| source | 来源文件或会议片段 |
| confidence | 模型置信度 |

### 第三步：和人工基准逐项比对

用人工基准的 29 条任务作为 gold set，逐项标注：

| 维度 | 记录方式 |
|---|---|
| 召回 | hit / missed |
| 误提 | false_positive / acceptable_context |
| 负责人 | exact / partial / wrong / missing |
| 截止时间 | exact / coarser / hallucinated / missing |
| 完成标准 | preserved / weakened / invented / missing |
| 去重 | unique / duplicate |

### 第四步：只把高质量结果放入试点

进入钉钉交互试点的任务必须满足：

1. 不是误提。
2. 负责人能明确落到 roster，或明确标记为待补充。
3. 截止时间没有编造。
4. 完成标准没有编造。
5. 重复项已合并。

不满足条件的候选任务只保留在评测报告里，不进入正式 TDL 流程。

## 四、通过标准

第一轮小样本通过标准：

| 指标 | 最低标准 |
|---|---|
| 基准任务召回率 | >= 70% |
| 误提率 | <= 15% |
| 负责人正确率 | >= 80% |
| 明确截止时间保留率 | >= 80% |
| 截止时间编造数 | 0 |
| 完成标准编造数 | 0 |

如果召回率不足但误提率低，可以继续优化提示词。

如果出现截止时间或完成标准编造，优先修正提示词和结构化约束，不进入用户试点。

## 五、与日常 TDL 试点的边界

日常任务助手当前只给 Frank 和李珍做可控试点。

会议录入试点在质量未达标前不推送给其他管理者，也不批量生成正式任务。它只使用离线材料和人工基准做验证。

## 六、模块化路线纳入方式

本轮先执行 `design/11-模块化架构方案.md` 的第一层：

1. 先固定模块依赖地图和验收标准。
2. 会议录入先补离线验收能力，再接入正式交互。
3. 暂不做接口契约重构，避免在试点质量未稳定前扩大改动面。

第二层接口契约应放在会议录入第一轮试点结束后执行，优先抽象：

1. `TDLStore`
2. `MessagePort`
3. `Tagger`

第三层插件化能力暂不进入当前冲刺，只保留为后续扩展方向。

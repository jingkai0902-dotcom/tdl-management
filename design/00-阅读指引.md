# 00 · 阅读指引

## 这些文档是什么

TDL 管理层待办系统的完整设计方案。从"为什么做"到"怎么写代码"，再到试点验收和协作流程，逐层展开。

## 文档地图

```
00-阅读指引          ← 你在这里
    │
01-要解决的问题      为什么做、给谁用、分几个阶段
    │
02-数据模型与标签    系统里记录什么信息、怎么分类
    │
03-功能模块          五个模块分别做什么、怎么协作
    │
04-交互方式          日常怎么跟系统对话
    │
05-技术实现方案      用什么技术、部署在哪里
    │
06-开发计划          分几个批次开发、每批验收什么
    │
07-暂存需求决策记录  当前不进 MVP、但后续不能丢的真实需求
    │
08-AI转型框架对照    用企业AI转型方法论审计当前设计的完成度，指出差距
    │
09-Cowork接手指南    Codex/Cowork 额度切换时的上下文交接与接手口径
    │
10-Codex-Claude协作  Codex 主开发、Claude 审 PR、合并与部署的标准流程
    │
10-TDL试点测试方案    日常任务助手的可控试点测试动作和验收标准
    │
11-模块化架构方案     模块边界、接口契约和插件化扩展路线
    │
12-会议录入试点方案   月会材料小样本试点、人工基准和评测口径
```

## 怎么看

- **快速了解全貌**：读 00 → 01 → 03（每个模块标了 ✅ MVP / 🔮 第 2 阶段，末尾有不做清单）
- **细读每个设计点**：按顺序 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08
- **评估 AI 化准备度**：读完 01-03 后跳 08，了解当前设计在"专家经验产品化"上的差距
- **复用开发协作流程**：读 10，按 Codex 主开发 + Claude 审核 PR 的 SOP 推进
- **推进试点验收**：日常任务助手读 10-TDL试点测试方案；会议录入读 12
- **做后续架构演进**：先读 11，再按 12 的试点结果决定是否进入接口契约层
- **只看一个具体问题**：跳到对应文档，每篇开头有「这篇跟其他文档的关系」

## 每篇文档会标注

| 标注 | 含义 |
|------|------|
| ⚠️ 待你确认 | 我从知识库里推断的，需要你验证或修正 |
| ✅ 已确认 | 你明确说过的事实或决定 |
| 💡 设计考量 | 为什么这么设计而不是那样，不确认也没关系 |

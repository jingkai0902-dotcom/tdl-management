## 怎么看

- **快速了解全貌**：读 00 → 01 → 03（每个模块标了 ✅ MVP / 🔮 第 2 阶段，末尾有不做清单）
- **细读每个设计点**：按顺序 01 → 02 → 03 → 04 → 05 → 06 → 07 → 08
- **评估 AI 化准备度**：读完 01-03 后跳 08，了解当前设计在"专家经验产品化"上的差距
- **复用开发协作流程**：读 10，按 Codex 主开发 + Claude 审核 PR 的 SOP 推进
- **推进试点验收**：日常任务助手读 10-TDL试点测试方案和 23；会议录入读 12
- **判断日常助手当前能不能继续用**：读 23，再回看 14
- **控制额度和决定何时用 UI**：读 24，再回看 10
- **做后续架构演进**：先读 11，再按 12 的试点结果决定是否进入接口契约层
- **只看一个具体问题**：跳到对应文档，每篇开头有「这篇跟其他文档的关系」

## 新对话的最小首读集

新开对话时，不要先把全部历史文档重新读一遍。先按任务类型读取最小集合；只有被阻塞时，再追加其他文件。

| 当前任务 | 先读这几份 |
|---|---|
| 想快速续上项目全局 | `AGENTS.md`、`17`、`18 V2`、`19` |
| 做 PR / review / 合并 | `AGENTS.md`、`10`、`24` |
| 做生产部署 / 健康检查 | `AGENTS.md`、`24`、`README.md` |
| 做钉钉真实交互验证 | `AGENTS.md`、`14`、`23`、`24` |
| 做日常 TDL 功能开发 | `AGENTS.md`、`18 V2`、`23`、再按功能补读相关代码 |
| 做会议录入 / gold set | `AGENTS.md`、`16`、`22`、再读对应 gold set 文件 |
| 做系统设计或路线判断 | `AGENTS.md`、`17`、`18 V2`、`19` |
| 想追历史为什么这样定 | `AGENTS.md`、`00-项目演进全记录.md`、必要时再补 `21` |

执行原则：

1. 默认只先读 `2 到 4` 份最相关文件。
2. `AGENTS.md` 用来快速建立项目级上下文；设计判断仍以具体正式文档为准。
3. 如果用户新开对话只说“继续”，Codex 应先按当前任务类型选最小首读集，再向前推进，而不是要求用户重新复述全部历史。

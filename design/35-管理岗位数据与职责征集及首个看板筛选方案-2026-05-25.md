# 35 · 管理岗位数据与职责征集及首个看板筛选方案 - 2026-05-25

## 一、本文定位

本文承接：

1. `34-企业工作台正式路线原则与首阶段推进-2026-05-25.md`。
2. 已合入的统一首页只读信息架构原型。

本文用于落实 `34` 号文档的业务工作线 B：

> 先获得各管理岗位真实维护的数据、职责和协作动作，再决定第一个经营数据看板做什么、从哪里取数、由谁确认。

本文是征集和筛选方案，不是数据接口或生产功能开发授权。

## 二、本阶段要回答的问题

统一首页已经能够表达未来工作台的结构，但“经营数据”“资料与报告”目前不能凭假设填充。本阶段需要回答：

1. 每位管理者目前实际在维护什么表、文档、群消息或周期性汇报。
2. 哪些数据确实影响管理判断，哪些只是留档或重复报送。
3. 每项数据的定义、产生频率、负责人、审核人、查看范围和敏感级别是什么。
4. 哪些数据适合先转成固定结构或飞书多维表格入口。
5. 哪个业务场景最适合成为第一个经营数据看板试点。
6. 老板视角与岗位视角需要如何共享同一份中心数据，而不是复制多份表格。

本阶段不直接回答：

1. 飞书是否成为正式主数据源。
2. 正式文件上传和解析链路如何开发。
3. Agent 如何写入中心平台。
4. 权限系统如何在代码中完整实现。
5. 自动报告何时发布。

这些内容要在获得真实样本、确认首个试点后另行设计。

## 三、征集原则

### 3.1 以真实正在使用的资料为准

不先询问“你希望有一个什么样的高级看板”，而先询问：

1. 你上周或上月实际填写过哪些表。
2. 你实际向谁汇报过哪些数字、进展或问题。
3. 你在做判断前实际需要翻看哪些资料。
4. 哪些数据目前靠人工催、人工汇总或个人电脑保存。

应优先收集原表样例、空白模板、截图或脱敏副本，而不是只有口头描述。

### 3.2 数据与管理动作必须对应

一个候选数据只有能回答具体管理问题时，才值得进入看板。例如：

| 数据示例 | 应回答的管理问题 |
|---|---|
| 招生咨询、到访、签约、转化 | 本月销售结果偏差出在哪里，需要谁采取动作 |
| 学员流失或续费预警 | 哪些班级需要教务跟进、哪些问题需要教学介入 |
| 教师培训和课堂评价 | 哪些老师需要培养、哪些课程质量风险需升级 |
| 招聘进展和人员缺口 | 哪些岗位影响业务进度，需要何时补齐 |

无法对应管理动作的展示项，不优先做成看板。

### 3.3 权威来源和敏感性必须一开始记录

任何进入试点候选的数据，必须记录：

1. 当前原始来源在哪里。
2. 谁对数据正确性负责。
3. 谁能查看原始数据，谁只能看汇总。
4. 是否涉及学员、家长、教师、员工、薪资或绩效等敏感信息。
5. 后续若迁移到中心平台，原资料是否必须保留作为证据。

### 3.4 教学与教务分别征集

必须保持 `34` 号文档已确认的职责区分：

| 视角 | 本次征集重点 |
|---|---|
| 教学 | 教师培训、课程质量、教研标准、课堂能力提升及教学管理动作 |
| 教务 | 班主任团队、学员服务、家校沟通、续费/流失协同、对教学侧的服务反馈 |

不能因为目前部分人员职责交叉，就把教学和教务的数据需求合并成一个模糊板块。

### 4.1 角色范围

基于当前路线与管理花名册，第一批覆盖以下岗位视角：

| 视角 | 建议访谈对象 | 征集重点 | 备注 |
|---|---|---|---|
| 老板 / 总负责人 | Helen / 李珍 | 全局经营判断、跨部门风险、需拍板事项、报告期待 | 作为业务体验和最终看板价值的主参照 |
| 销售 / 市场 | 时颖 / Sherry；必要时补斯坦侧负责人 | 招生转化、活动、客户分类、销售协作 | 适合寻找结构化指标候选 |
| 教学 | 张蕾 / Teresa；结合 Frank 的斯坦教学经验 | 教师培养、教学质量、教研推进 | 与教务分开记录 |
| 教务 | 赵晓华 / Doris；斯坦侧后续补充 | 班主任、学员服务、家长反馈、续费协作 | 与教学分开记录 |
| 人力 | 张皓 / Allen、许梦冉 / Rachel | 招聘、留存、培养、绩效和敏感数据边界 | 敏感级别需重点确认 |

上述人员用于启动征集，不意味着其权限模型或看板内容已经正式确定。

### 4.2 建议顺序

| 顺序 | 动作 | 原因 |
|---:|---|---|
| 1 | Helen 先确认最想持续看到的经营问题和需拍板信息 | 先明确老板视角价值标准 |
| 2 | 销售 / 市场与教务分别收集现有数据 | 两者更可能快速形成经营判断和行动闭环 |
| 3 | 教学收集质量与培养数据 | 与教务协作场景需要一并核对 |
| 4 | 人力收集数据，但先只做敏感性和可用性判断 | 避免过早将敏感数据用于原型 |
| 5 | 技术管理整理数据入口、格式与维护成本 | 基于真实资料判断技术实现路线 |

## 五、征集包内容

每位访谈对象不要求先写长文。一次征集包应包含以下四类信息：

1. 岗位职责与周期性工作。
2. 当前真实数据或资料清单。
3. 典型管理判断与跨部门流转。
4. 对工作台看板和录入方式的需求。

### 5.1 岗位职责卡

```text
姓名 / 岗位：
所属品牌 / 部门：
直接汇报对象：
你负责的三个最重要结果：
每周固定要推进的工作：
每月固定要产出的结果或汇报：
当前最容易漏掉、拖延或难以追踪的事项：
需要其他部门配合的固定场景：
哪些事项必须由你本人判断或确认：
哪些信息不应向全体管理者公开：
```

### 5.2 当前数据与资料清单

请对每一张实际维护的表、文件、汇报或记录分别填写一行：

| 字段 | 填写要求 |
|---|---|
| 资料名称 | 目前真实使用的名称 |
| 业务用途 | 它帮助你做什么判断或交付什么结果 |
| 内容类型 | 表格 / 文档 / 群消息 / 系统导出 / 图片 / 其他 |
| 当前存放位置 | 个人电脑 / 钉钉 / 飞书 / 本地文件夹 / 其他 |
| 维护人 | 谁实际录入和更新 |
| 审核或确认人 | 谁负责判断是否正确 |
| 使用者 | 谁会查看或据此采取动作 |
| 更新频率 | 实时 / 日 / 周 / 月 / 事件触发 |
| 时间维度 | 日 / 周 / 月 / 季 / 年 / 单次事项 |
| 关键字段 | 最重要的 3 至 10 个字段 |
| 当前痛点 | 重复填写、口径不一、无法汇总、容易遗失等 |
| 敏感级别 | 普通 / 部门受限 / 管理层受限 / 高敏感 |
| 是否可提供样例 | 原件 / 脱敏副本 / 空白模板 / 暂不可提供 |

### 5.3 单项数据定义卡

对于可能进入看板的关键数字或状态，需进一步记录：

```text
指标或状态名称：
它回答的管理问题：
业务定义 / 计算口径：
最小数据粒度：（个人 / 班级 / 校区 / 部门 / 公司）
时间周期：（日 / 周 / 月 / 季 / 年）
原始来源：
录入人：
确认人：
查看范围：
异常阈值或需要关注的条件：
出现异常后应由谁采取什么动作：
是否需要保留原始证据：
是否适合进入首个看板试点：
```

### 5.4 跨部门协作场景卡

只有数据而没有流转动作，看板会停留在展示层。对真实协作场景记录：

```text
场景名称：
发起岗位：
接收 / 配合岗位：
触发条件：
需要传递的数据或材料：
接收方需要做出的判断或动作：
完成标准：
预计完成时限：
当前通过什么方式流转：
当前最容易卡住的位置：
这类事项应属于任务、议题、线索、资料还是指标异常：
```

特别关注的跨岗验证场景包括：

1. 教务发现续费或服务风险，教学是否需要接收质量改进信号。
2. 教学发现教师能力风险，教务是否需要同步家校沟通或班级安排。
3. 销售发现转化异常，老板或相关岗位需要看到什么证据后拍板。
4. 人力发现岗位缺口，业务部门如何确认优先级和时间要求。

## 六、资料交付与安全边界

### 6.1 本轮允许收集的材料形态

优先顺序如下：

1. 空白模板或字段截图。
2. 脱敏后的历史样例。
3. 经 Frank / Helen 明确确认可用于研究的原件。
4. 口头描述，作为缺少材料时的补充，不作为数据口径最终依据。

### 6.2 敏感资料处理

在身份、权限与审计能力未实现前，本轮不得将以下原始敏感内容导入工作台页面：

1. 员工薪资明细、绩效评价明细。
2. 学员或家长的个人识别信息、联系方式和投诉原文。
3. 教师个人考核或离职预警明细。
4. 任何仅限少数人员访问的人事或财务资料。

此类资料可以记录“存在该类数据、字段结构和看板需求”，但样例应先脱敏或只保留空白模板。

### 6.3 当前数据归属口径

本轮资料征集不改变主数据归属：

1. 现有原件仍由当前责任人保管。
2. 征集表只记录来源、字段、管理价值和敏感性。
3. 未完成主数据权威策略、权限和审计设计前，不把飞书多维表格或工作台视为正式数据归档处。

## 七、飞书多维表格候选评估

飞书多维表格在本阶段仅作为候选输入形态评估，不直接获准接入。

### 7.1 适合成为候选的数据

同时满足多数条件的数据，可列入飞书候选清单：

1. 字段相对固定，口径能在短期确认。
2. 多人需要按周期填报或协作更新。
3. 数据敏感级别可控，或可通过权限清晰隔离。
4. 当前人工合表、重复传表或版本混乱的痛点明显。
5. 负责人能够验证迁移后是否提高效率。

### 7.2 暂不适合直接转换的数据

1. 定义仍争议较大的指标。
2. 高敏感原始数据，且权限设计未形成。
3. 主要价值在原件证据、无法只靠结构化字段表达的材料。
4. 需要复杂审批、不可逆处理或正式发布责任的内容。

### 7.3 候选登记表

| 数据/表格 | 当前岗位 | 适合转飞书的原因 | 不适合或需先解决的问题 | 候选结论 |
|---|---|---|---|---|
| 待征集 | 待填写 | 待填写 | 待填写 | 待评估 |

## 八、AI / 口述辅助录入候选评估

本阶段只识别候选场景，不接入 Agent 写入。

优先考虑：

1. 口述后可以生成结构化草稿，且本人能在提交前核对的记录。
2. 重复、低风险、原本录入成本高的日报或状态补充。
3. 原始语音或文字能够保留，便于审计和纠错的场景。

暂不考虑：

1. AI 自动判断并发布正式经营结果。
2. AI 直接确认任务、修改状态或替代负责人拍板。
3. 高敏感数据的无审核录入。
4. 无法保留原始材料或确认记录的输入。

候选记录字段：

```text
录入场景：
当前录入方式和耗时：
口述 / AI 可能减少的步骤：
必须由本人确认的字段：
原始材料保存方式：
错误录入的影响：
是否适合后续小范围测试：
```

## 九、首个经营数据看板试点评分

征集结束后，对候选看板统一评分，不凭感觉拍板。

### 9.1 评分维度

每项按 1 至 5 分评分：

| 维度 | 评分问题 | 高分含义 |
|---|---|---|
| 管理价值 | 是否直接帮助 Helen 或岗位负责人做判断 | 能触发明确行动或拍板 |
| 样本可得性 | 是否能获得真实、合法可用样本 | 有近期样本且可验证 |
| 口径稳定性 | 字段和定义是否能较快固定 | 定义清楚、争议少 |
| 权限可控性 | 数据暴露风险是否可控 | 普通或可脱敏数据 |
| 双视角价值 | 是否既支持岗位页，也支持老板汇总页 | 两端都能回答问题 |
| 录入改进空间 | 是否存在明显人工维护痛点 | 改造收益明显 |
| 实现复杂度 | 做出只读看板是否轻量 | 不依赖复杂集成或写入 |

### 9.2 选择规则

候选场景只有同时满足以下条件，才可进入首个看板设计：

1. 管理价值、样本可得性、口径稳定性、权限可控性四项均不低于 3 分。
2. 有明确业务负责人愿意校验展示结果。
3. 可先以只读方式验证，不要求直接开放数据写入。
4. 不依赖尚未批准的 Agent、上传链路或自动报告能力。

### 9.3 候选比较表

| 候选看板 | 负责人 | 管理价值 | 样本可得 | 口径稳定 | 权限可控 | 双视角价值 | 录入改善 | 实现复杂度 | 总结论 |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|
| 待征集 | 待填写 | - | - | - | - | - | - | - | 待评分 |

## 十、执行方式与产出

### 10.1 建议执行步骤

| 步骤 | 动作 | 产出 | 完成标准 |
|---:|---|---|---|
| 1 | Helen 确认老板最关心的 3 至 5 个经营判断问题 | 老板判断问题清单 | 每个问题能说清需要什么事实支持 |
| 2 | 对销售、教学、教务、人力、技术分别进行资料征集 | 岗位职责卡 + 资料清单 | 每个岗位至少收集一份真实模板或脱敏样例，无法提供时记录原因 |

### 10.2 本轮最终产出清单

1. 已填写的岗位职责卡。
2. 各岗位当前资料与数据清单。
3. 候选数据定义及敏感性清单。
4. 飞书多维表格候选列表。
5. AI / 口述辅助录入候选列表。
6. 首个经营数据看板试点评分和建议。

## 十一、可直接发给管理者的征集说明

```text
我们正在设计公司管理工作台的下一阶段数据看板。现在不是让大家更换系统，也不是要求立刻重新填表，而是先了解你目前实际维护的数据和工作流。

请准备以下内容：
1. 你目前每周、每月实际维护或提交的表格、文件、汇报或数据记录名称。
2. 最好提供一份空白模板、截图或脱敏样例；涉及薪资、绩效、家长和学员个人信息的内容请先不要直接提供原始明细。
3. 说明每份资料用于做什么判断，由谁填写、谁确认、谁查看、多长时间更新一次。
4. 说明你最容易出现重复填写、找不到数据、无法汇总或跨部门沟通卡住的地方。
5. 说明如果有一个岗位专属看板，你每天或每周最想优先看到哪三项信息，以及看到异常后你会做什么。

本轮资料仅用于评估看板需求、数据口径、权限风险和首个试点场景，不会直接把你的资料自动录入正式系统，也不会开放 AI 自动处理或发布。
```

## 十二、当前边界与下一步

本文确认可以立即开始人工征集和样本评估，但不批准：

1. 将征集资料直接上传到生产工作台。
2. 将个人电脑中的资料自动集中到中心平台。
3. 将飞书多维表格作为正式主数据源。
4. 让 AI / Agent 自动录入、审核、修改或发布数据。
5. 在权限和审计未设计前展示敏感数据。

待实际收集至少第一批岗位资料后，下一份设计文档应给出：

1. 哪个看板场景最值得先做。
2. 该场景需要哪些字段、数据来源、可见范围和审核责任。
3. 是否适合采用飞书作为输入候选。
4. 是否能够继续只读验证，还是已到必须设计写入与权限的时候。

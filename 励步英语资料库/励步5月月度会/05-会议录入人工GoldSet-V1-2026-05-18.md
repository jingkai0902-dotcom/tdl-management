# 励步 5 月月度会会议录入人工 Gold Set V1 — 2026-05-18

## 1. 本文件定位

本文是按 `design/22-会议分类Schema与GoldSet设计-2026-05-18.md` 重新建立的第一版人工基准。

它与旧文件 `00-人工提炼基准任务清单-2026-05-17.md` 的关系是：

1. `00` 号文件保留为旧口径下的历史对照。
2. 本文件才是后续会议分类模型、会议 evaluator 和 `PR-C` 之后工作的当前人工基准。
3. 旧口径把大量个人述职计划直接纳入“任务基准”；新口径必须先区分：
   - 会议原文中的组织事实
   - 会议中真正达到执行阈值的事项
   - 个人提报中的计划
   - 仍待讨论的议题
   - 只值得保留的火花和观察线索

### 2.2 为什么没有硬凑满 44 条

按新口径回看，5 月材料中真正可供标成 `confirmed + Task` 的样本暂未找到。  
如果为了满足数量硬把个人述职计划也写成 `confirmed`，就会重新犯“把提报当决议”的旧错误。

因此，V1 采用以下原则：

1. 先保证标签准确。
2. 再在后续更多会议材料中扩充样本。
3. `confirmed + Decision` 暂先保留 2 条，后续随着更多真实会议样本再补足。

## 3. 口径提醒

### 3.1 旧基准不再直接代表当前标准

旧基准里的以下类型内容，本轮一律不能直接视为 `confirmed`：

1. 时颖述职中的 5 触点 SOP、Riley 培养、周年庆直播等计划。
2. HR 述职中的新师成长机制、招聘结构优化、校企合作推进等计划。
3. 教务、教学、新师培训材料中的月度安排。

它们可以很有价值，但当前身份更接近：

- `pending + Issue`
- `spark + Idea`
- 或个人提报中的 `plan / proposal`

而不是已经由组织统一确认的 `confirmed + Task`。

### 3.2 `confirmed` 的严苛门槛

只有同时具备：

1. `What`
2. `Who`
3. `When`

且三者都能从原始材料直接找到证据，才允许进入 `confirmed`。

## 6. 对旧基准的修正

### 6.1 旧基准中应降级的典型项

| 旧项 | 旧身份 | 新身份 |
|---|---|---|
| `B1` 完成 5 触点 SOP 设计并跨部门对齐 | 任务基准 | 个人提报计划，暂按 `pending / plan` 看待 |
| `B7` Riley 5-8 月考核、9 月任命判断 | 任务基准 | 个人提报计划 |
| `C3` 以 15 名新师试运行成长支持机制 | 任务基准 | 部门计划 |
| `D5-D9` 二公三公、公开课、Rebuy、重点老师帮扶 | 任务基准 | 部门月度计划，是否升格为组织事项需另行确认 |
| `E1-E3` WSDA 辅导、市场外化、新师培训 | 任务基准 | 专项计划，不自动等同组织决议 |

### 6.2 旧基准中仍有价值但需重新解释的项

| 旧项 | 保留价值 |
|---|---|
| `A1-A3` | 是会议中最接近组织级动作的一组，但目前仍未越过 `confirmed` 门槛 |
| `A4` | 可保留为已明确推进方向，但目前更像 `confirmed + Decision`，未必直接是 TDL |
| 销售、人力、教学各部门计划 | 是理解经营脉络的重要输入源，可用于 `pending / spark / signal`，不能直接当 TDL gold set |

## 7. 本轮人工结论

### 7.1 对会议录入能力的真正考验

真正难点已经不是“能不能从材料里抽出一些像任务的话”，而是：

1. 能不能识别哪些只是个人计划。
2. 能不能识别哪些只是经营线索。
3. 能不能在看到一个很完整的方案时，仍然克制地承认“它还没有被组织确认”。

### 7.2 对后续模型评测的要求

从本文件开始，模型只有在以下方面同时表现合格，才算真正通过：

1. 不把 `spark / signal / pending` 误判成 `confirmed`
2. 不把个人述职直接升格为组织决议
3. 如果材料中没有真正 `confirmed + Task`，模型也必须能接受“0 条任务”的结果
